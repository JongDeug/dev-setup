## 이 스킬이 정하는 것

**노션 작업 페이지의 본문 양식 하나**다. DB 좌표·속성·전체 작업 흐름은 `task-flow` 가 갖고 있다 —
여기서 다시 적지 않는다. 티켓을 만들 때 `task-flow` 0단계의 중복 검사(최근 30건 조회)를 먼저 지나야 한다.

본보기: [M1Insight 이용한 tlog 조회·다운로드](https://app.notion.com/p/3d495aca9e2e8185b617c967e34a1d12)

## 층 나누기 — 이 한 줄이 전부다

> 본문은 **과업에 대한 상세 정의**, 또는 **과업이 끝나도 유효한 사실**로만.
> 완료되면 역할이 끝나는 것, 진행 당시에만 의미있던 메모성 컨텐츠는 하위 페이지로.

팀 리뷰에서 받은 규칙이다. 문장 하나를 어디 둘지는 이 질문으로 가른다 —
**"이 작업이 끝난 6개월 뒤에도 누가 이걸 근거로 쓸까?"**

| 본문 | 하위 페이지 |
|---|---|
| 무엇을 만드나 · 왜 이게 단순한 일이 아닌가 | MR 목록, 배포 순서, 체크리스트 |
| 계약 — 경로·시각·포맷·인가처럼 다음 사람이 어길 수 없는 것 | 실측 수치, 검증 기록, 벤치 결과 |
| 채택한 안과 **채택하지 않은 안의 이유** | 코드 점검·리뷰 대응 항목 |
| 아직 안 정한 것과, 정하면 뭘 건드려야 하는지 | 진행 상태 체크박스, "오늘 한 일" |
| 코드 좌표(파일:라인) | 그날그날의 판단 이력 |

하위 페이지 이름은 관례가 있다 — `작업 메모 — MR·배포·검증`, `코드 점검 — 개선 항목 ({sha})`.

## 본문 골격

블록 셋이다. 더 늘리지 않는다.

```md
## 🎯 무엇을

<한 줄 정의 — 사용자 동선으로. "로봇 클릭 → 비행 시간 → 로그 다운로드">

<왜 단순 작업이 아닌가 2~3줄. 여기가 이 페이지에서 제일 중요하다.>

## 📐 계약 — 과업이 끝나도 유효한 것

- **경로** — …
- **시각** — …
- **인가** — …

**📎 하위 기록**
<하위 페이지 링크>
```

- 제목은 **H2 두 개까지**. H3 로 더 쪼개면 목차가 계약보다 길어진다
- 계약은 **`**라벨** — 본문` 불릿 한 줄**이 기본 단위다. 라벨만 훑어도 뭘 정했는지 보이게
- 제목에 이모지를 붙인다. 페이지 아이콘은 상태용이라 따로다 (⏳ 진행 중 → ✅ 완료)

## 쓰지 않는 것

- **공백으로 칸 맞춘 코드블록** — 노션 코드블록은 가로 스크롤이라 오른쪽 주석이 잘린다.
  단계·비교는 **3열 이하 표**로. 파이프라인이면 `단계 | 하는 일 | 실패하면`
- **`[[위키링크]]`** — 옵시디언 문법이라 노션에선 맨 텍스트다. 노션 링크나 하위 페이지로 바꾼다
- **표 남발** — 축이 둘 이상일 때만 표다. `A는 X, B는 Y` 한 문장이면 문장으로
- **진행 상태 트리**(`[✓] 구현 [✓] 배포 [ ] 검증`) — 통째로 하위 페이지
- 목표/범위/리스크 같은 빈 섹션 템플릿

## 근거는 코드에서 뽑는다

계약 줄은 **읽고 확인한 것만** 쓴다. 상수·정규식·게이트는 값과 함께 적고, 코드 좌표 블록에
`파일:라인` 을 남긴다. 옵시디언 노트가 정본이면 노트에서 **계약 층만** 뽑고 수치·검증은 두고 온다
(노트 위치는 `Project/모빌리티원/태스크/{작업}/`).

노트와 코드가 어긋나면 코드가 이긴다. 어긋난 사실 자체를 한 줄로 남긴다.

본문의 「코드 좌표」는 그 작업 폴더의 `진입점.md`(레포별 트리)를 요약한 것이다 — 트리 전체를 노션에 옮기지 않는다. 양식은 `task-flow` 12단계.

## 절차

### 만들 때

1. `task-flow` 0단계로 **중복부터 확인**한다 — 같은 일이 이미 있으면 그 페이지를 쓴다
2. 속성(작업 이름·상태·유형·담당자·시작일)은 `task-flow` 의 `notion-create-pages` 호출 그대로
3. 본문은 위 골격으로. **계약이 아직 없으면 「🎯 무엇을」만 쓰고 비워 둔다** — 지어내지 않는다
4. 진행 메모가 생기면 그때 하위 페이지를 만든다. 처음부터 빈 하위 페이지를 깔지 않는다

### 정리할 때 (기존 페이지)

1. `notion-fetch` 에 `include_discussions: true` → 댓글 있으면 `notion-get-comments`
   (`include_all_blocks: true`). **댓글이 요구한 게 있으면 그게 정리의 기준이다**
2. 본문을 층으로 가른다. 내릴 것은 **지우지 말고 하위 페이지로 옮긴다**
3. **쓰기 직전에 다시 `fetch` 한다** — 사용자가 동시에 편집 중일 수 있다
4. 부분 수정은 `update_content`(정확한 문자열 치환), 전면 교체만 `replace_content`.
   `replace_content` 는 새 본문에 하위 페이지 태그(`<page url="...">`)를 그대로 넣어야 안 지워진다
5. 사용자가 편집 중이라고 하면 **쓰지 말고 고칠 문구만 준다**

### 댓글에 답할 때

답글·해결 처리는 **사람에게 나가는 글**이다. 임의로 쓰지 않고 사용자에게 확인받는다.

## 하지 않는 것

- 승인 없이 작업 페이지 생성 — 중복 검사부터
- 본문 내용을 **삭제** — 층이 안 맞으면 하위 페이지로 옮긴다
- 검증 안 한 계약 줄 쓰기 — 코드로 확인 못 했으면 "미확인"이라고 적는다
- 노션 댓글에 임의로 답글 달기·해결 처리
- 옵시디언 노트를 노션에 통째로 복사 — 노트가 정본이고 노션은 계약 층만이다
